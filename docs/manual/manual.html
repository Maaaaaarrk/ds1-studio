1Getting started ↑ Contents

DS1 Studio opens the map presets (DS1 files) of classic Diablo II and your mod straight from the game's files, draws them the way the game does, and lets you edit their tiles, objects, the game's level tables, the automap and the tile libraries (DT1 files) themselves. See the Glossary for any term you don't know.

1.1Installing

Download the latest version from the Releases page on GitHub:

SystemFileNotes
Windows 10/11…_x64-setup.exeRecommended. Installs for your user and updates itself.
…_x64_en-US.msiFor managed installs.
Linux….AppImageRuns on most distributions; make it executable and double-click. Updates itself.
….deb / ….rpmDebian/Ubuntu, Fedora/openSUSE packages.
Note The Windows installer isn't code-signed yet, so Windows may say “Windows protected your PC”. Click More info → Run anyway.

1.2First start: choosing your folders

The first time it runs, DS1 Studio asks for two folders:

  • Diablo II — the folder with d2data.mpq, d2exp.mpq and patch_d2.mpq. It is only ever read.
  • Mod folder (optional) — your mod's folder with its data/ tree. This is where everything you save goes (see Saving). Tick Also read the mod folder's own .mpq files if your mod ships its data in MPQs.

On Linux, point it at the Diablo II folder inside your Wine prefix. You can change the folders later with Home → File → Folders… Nothing else is needed: object names and sprites come from the game's own files, and special tiles get DS1 Studio's own markers.

1.3A tour of the window

  1. 1Tabs: Home, Map, Data and Help switch the ribbon below.
  2. 2Ribbon: the commands, in labelled groups (File, Edit, Tools, Paint / erase, Layer, View…). Hover any button for what it does and its shortcut.
  3. 3Suggest a feature and the open map's name and path. A dot after the name means unsaved changes.
  4. 4Presets list: every DS1 in the game and your mod. Type in the box to filter (see Opening a map).
  5. 5Map view: the map as the game draws it (see Viewing maps).
  6. 6Minimap: the whole map; click it to move there (2.2).
  7. 7Side panels: Tiles/Presets, Selection, Cell, History, Layers, Map… (they change with the tool).
  8. 8Status bar: the data sources, the tool and layer, the cell under the mouse, zoom, size and act.

1.4Opening a map

  1. Type part of the path in the box above the presets list, e.g. act1/town or arcane.
  2. Click a map in the list. It opens with the tile libraries the game would use for it (from LvlPrest.txt → Levels.txt → LvlTypes.txt) and the right act palette.
  3. Press F to fit the whole map in the view.

You can also reopen a recent map (1.7), create a new one (3.9) or import one (7.1).

1.5Saving, and where files go

Save (Ctrl+S) writes the map into your mod folder, under the same path it has in the game. If a file is replaced, the original is kept next to it as <name>.bak (only the first time, so the true original survives). Save as… saves under a new path. Your Diablo II install is never written to.

Everything else DS1 Studio writes — edited DT1s, .txt tables, presets — also goes into the mod folder with the same .bak safety. See Safety and troubleshooting.

1.6Autosave and recovery

While a map has unsaved changes, DS1 Studio keeps a copy of it every 20 seconds in its own storage (never in your game or mod folders). If the app crashes or is closed without saving:

  • the start page lists Unsaved work kept from an earlier session, and
  • opening that map offers Restore (the autosaved version opens, unsaved until you save) or Discard them.

Saving, or undoing back to the saved state, removes the kept copy.

1.7Recent maps

Home → File → Recent ▾ lists the maps you opened last; the start page lists them too. Tick Reopen the last map on start to have your last map open automatically.

1.8Updates

The app checks GitHub once a day and tells you when a new version is out. Help → Check for updates downloads and installs it and restarts DS1 Studio. Help → About shows the version and build.

2Viewing maps ↑ Contents

2.1Moving around and zooming

ZoomMouse wheel (zooms around the mouse)
PanArrow keys (Shift = faster), Space + drag, or drag with the middle or right mouse button
Fit the whole mapF
Jump anywhereClick or drag on the minimap

At 100% you see exactly the game's pixels; zoomed out, tiles are properly downscaled instead of turning grainy.

2.2The minimap

The bottom-left corner shows the whole map with the visible area outlined. Click or drag on it to move the view there. Toggle it with K or View → Minimap.

2.3Layers: showing and hiding

A map has up to 2 floor layers, 4 wall layers (walls, roofs, lower walls, special tiles, trees and objects that are tiles), shadows, and optionally a tag layer.

The Layers panel shows or hides each one and says how many cells it uses. The number keys toggle them too: 1/2 floors, 3–6 walls, 7 shadows, 8 roofs, 9 lower walls, 0 special tiles.

Hiding a layer only affects the view. To edit a layer, make it the active layer (3.1).

2.4Grid, rooms, walkability, automap

Automap (A) draws the in-game automap over the map, as players will see it (see The automap).

Level light (Layers panel) draws the map as brightly and in the colour the game lights its level: Levels.txt's Intensity (1-255) and Red/Green/Blue; 0 means the act's own daylight, as towns and outdoor levels use. The Map panel shows and changes them (Level light: slider, colour, Apply to Levels.txt), previewing while you move the slider. In game the player's own light radius also brightens the area around them.

2.5Game view

Game view (Z) zooms to exactly what the character sees in game, centred on the selection, and shades everything else. Pick the screen size next to it: 640×480, 800×600, PD2's widescreen sizes, or a custom size.

2.6Objects, sprites and animation

Objects and NPCs are drawn with their real sprites, animated at the game's speeds, with fire, glows, magic and fog blended as in game. Sprites (N) toggles the sprites, M the object markers, P the NPC paths. Animated floor tiles (water, lava) animate too. See Objects and NPCs for editing them.

2.7Special tiles

Special tiles are invisible in game: they mark warps, where players arrive in town or on a map, the corpse and town-portal spots. DS1 Studio draws a labelled marker on each, e.g. Town entry 1, Map entry, Corpse location. Warps show where they lead, e.g. Warp · link 1 → Catacombs Level 1; see Warps: connecting maps.

Roof hiding

When a player walks into a building, the game fades its roof. This is set by a hide area: two special tiles (main index 8–29) at opposite corners of the inside, whose sub index is the main index of the tiles that fade. Every wall-layer tile with that number in the area, plus one cell around it, fades while the player stands inside. The trigger is the rectangle, grown or shrunk toward the south and east by LvlPrest's PopPad (in sub-tiles; the game's houses use −4). The game ignores hide areas unless LvlPrest's Pops counts them.

  • View → Hide areas (H) fills the area the player must stand in, outlines the area whose tiles can fade, and marks those tiles.
  • View → As if inside (Shift+H) hides those tiles, as the game shows the map while a player is inside.
  • Map → Roof hiding: select the inside of a building (the floor players walk on), open it, tick what should fade (roofs are ticked for you), and click Add hide area. DS1 Studio places the corner markers and sets Pops/PopPad. The dialog also lists and removes existing areas.
  • The Compatibility check reports hide areas the game would ignore (Pops 0 or too small) and markers it would merge into one rectangle, such as the same number used for two buildings.

2.8Overlapping (stacked) tiles

Trees over trees, a wall over a floor: when several tiles overlap under the mouse, hold Shift and turn the mouse wheel to step through them one at a time. Only that tile's layer is selected, so Copy, Cut and Delete leave the others alone; Esc selects all layers again. Clicking a tile also shows it in its DT1 in the Tiles panel.

3Editing tiles ↑ Contents

3.1The tools

ToolKeyWhat it does
SelectVClick a cell to inspect and edit it in the Cell panel; drag to select an area; Shift+click or Shift+drag adds to it (3.4).
PaintBPaints the tile chosen in the Tiles panel on the active layer.
EraseEClears cells on the active layer.
PickIClick a tile on the map to paint with it.
ObjectsOSelect, move, add and delete objects and NPCs (chapter 4). Tab switches between tile and object editing.

The Active layer list chooses which layer Paint, Erase, Fill and Clear work on. Floors take floor tiles; wall layers take walls, roofs, lower walls, trees, objects and special tiles.

3.2The Tiles panel

The Tiles panel shows every tile the map's libraries provide for the active layer.

  • Click a tile to paint with it (switches to Paint).
  • Ctrl+click more tiles to paint a random mix: each painted cell gets one of them. clear mix in the header goes back to one tile.
  • Right-click a tile to pin it (★) to the strip at the top; Recent lists what you used last. Both are remembered per tile set (level type).
  • The drop-down shows one DT1 at a time; on wall layers the chips filter walls, objects, roofs, lower walls and special tiles; the box finds a tile by main/sub number.
  • Ctrl+wheel over the panel zooms the thumbnails.
  • Rest the pointer on a tile for an enlarged view of it beside the panel (crisp pixels, up to 3×) with its size, variants, source DT1 and what clicking does. Thumbnails and this view are shown a little brighter than the game's dark palettes; the map and the files are unchanged.

3.3Painting: freehand, rectangle, fill

Paint and Erase work in three ways, chosen in the Paint / erase group:

ModeKeyHow
FreehandBPaints the cells the mouse passes over.
RectangleUDrag a rectangle; it's all painted (or erased) when you let go.
Fill areaLClick a cell: the connected area of the same tile is filled. If you click inside a selection, the fill stays inside it.
Tip Every stroke, rectangle or fill is one step to undo (3.6).

3.4Selecting, copying and moving

With Select (V), drag over the map to select cells, or press Ctrl+A for the whole map. Hold Shift to add to the selection: Shift+click adds one cell, Shift+drag adds a rectangle, so you can select any shape (an L-shaped room, a winding path). Everything below then works on just the selected cells. The Selection panel then offers:

  • Fill the active layer with the brush (or random mix); Clear the active layer; Clear everything (all layers and the objects standing there, Shift+Delete).
  • Copy (Ctrl+C), Cut (Ctrl+X) and Paste (Ctrl+V, then click where it goes). Objects and NPCs in the selection come along, so Cut then Paste moves an area with everything in it — even the whole map.
  • Re-roll and Find & replace… (3.5).

Empty cells paste as transparent. Hold Alt when you click to paste to stack the paste onto what's there (into the next free layer, adding layers as needed) instead of replacing it. Pasting into another map that doesn't load the copied tiles' DT1s offers to add them. Esc first drops what's on the cursor (a paste, an object, the paint tile), then deselects.

3.5Find & replace, re-roll

Find & replace (Ctrl+H, or Replace… on the ribbon) swaps every use of one tile for another, on every layer of the active kind or only the active layer, in the whole map or the selection. It starts with the selected cell's tile and your brush; Show them on the map marks every match. One step to undo.

Re-roll (Selection panel) mixes up the active layer inside the selection: each tile becomes a random tile of the same group (main index) already used there, so repeats are less visible. It never brings in tiles that weren't there.

3.6Undo and the History panel

Ctrl+Z undoes and Ctrl+Y redoes, without limit. The History panel lists every step by name (“Paint rectangle on Floor 1 (36 cells)”, “Paste 57×41 + 32 objects”…); click one to go back — or forward — to just after it. Map as opened undoes everything. Undoing back to the saved state counts as saved again.

3.7The Cell panel

Click a single cell with Select to edit everything in it. Each layer that has a tile is a card with the tile's picture and the DT1 it comes from (click the file name to show it in the Tiles panel). Every field has a ? that explains it:

  • Kind (orientation) on wall layers: left/right wall, corner, door, pillar/tree, roof, lower wall, special tile…
  • Main index and Sub index: the tile's number.
  • Present (prop1): 00 means empty.
  • Hidden in game: the game won't draw the tile.
  • Raw bytes: all four property bytes, to set every bit by hand.
  • Tag value on maps with a tag layer.

Empty layers are one line with Add (puts your brush tile there). × clears a layer. Warp tiles also show where they lead (chapter 6).

3.8Walkability: sub-tile flags

Painting walkability on the map (this map only). Turn on Walkability (W): the side panels make way for the Walkability panel and the map shows every sub-tile (5×5 per cell) that blocks walking (amber) or jumping and teleporting too (red). Choose Blocked or Walkable, what it blocks or allows (walking, jumping & teleport, sight & light, players only) and a brush (1×1, 3×3, 5×5 sub-tiles or a whole cell), then click or drag over the map. Shift+drag paints a rectangle and holding Ctrl does the opposite. Each stroke is one undo step; Done brings the other panels back.

It changes nothing for other maps. The game adds up the sub-tile flags of every tile in a cell, hidden tiles included, so blocking puts an invisible floor tile holding just those flags into a free floor layer of the cell (like Tal Rasha's tomb's own blockers), and making a sub-tile walkable that a tile blocks gives that cell its own copy of the tile without the flag (same picture and variants; a north-corner wall's other half comes along). Both go into a small tile library made for the map, <map>_walk.dt1 next to it, which is added to the map's tile libraries and level type. A cell whose two floor layers both hold real tiles has no room for a blocker; the panel says which cells it skipped.

Changing a tile everywhere. To change the flags of a tile itself, for every cell and map using it, use the Cell panel:

Every tile has 25 sub-tiles (a 5×5 grid over its floor diamond) whose flags decide where units can walk, see, shoot and teleport. Under each card, Sub-tile flags (walkability) shows them on the tile:

  1. Pick a flag (Block walk, Block light & sight, Block jump/teleport, Block player walk, Block missiles…). Hover a flag for what it does.
  2. Click or drag over sub-tiles to set it; start on one that has it to clear instead.
  3. Check the result on the map with Walkability (W).
  4. Save DT1s to mod in the bar at the top of the panel, or Discard.
Important The flags belong to the tile in its DT1: every cell and map using that tile changes. Change all variants (on by default) keeps the random variants of the tile alike.

3.9Resizing and new maps

Map → Resize shows handles on the four edges: drag them to add or remove cells (objects move with the cells). Resize… does it by numbers. Map → New map creates an empty map for a level type, size, act and number of layers; it's saved where Save path says. Use Add to game to make the game load it.

4Objects and NPCs ↑ Contents

4.1Placing from the gallery

  1. Switch to Objects (O, or Tab from a tile tool).
  2. In Objects & NPCs, filter by NPCs or Objects or type a name; every one is shown with its sprite.
  3. Click one, then click the map to place it. Keep clicking to place more; Esc stops.

The list is the act's placeable objects and NPCs, worked out from the game's own tables (and your mod's).

4.2Moving and editing objects

In object mode, drag an object to move it; Delete removes the selected one. The Preview panel animates the selected object in every direction. The Object panel edits its type, id, position, flags and its NPC path (the points an NPC walks between).

4.3“In this map”: find any object

In this map lists everything placed, grouped by name with a count (Chicken ×4…). Type to search by name or id. Click a name to select it and centre the view on it; click again for the next one of that kind.

5Presets ↑ Contents

A preset is a reusable piece of map — a building, a wall run, a group of trees.

  • Save selection (Map → Presets, or the Presets panel) stores the selected area as a preset in your mod folder, so it travels with the mod.
  • Suggest finds structures that recur across the maps sharing this map's tiles and offers them as presets.
  • Click a preset, then click the map to place it (like a paste; Alt stacks it onto existing tiles).

Open the panel with the Presets tab next to Tiles, or Map → Presets.

6Warps: connecting maps ↑ Contents

In Diablo II each map preset is its own level, and levels are joined by warps. A warp special tile with main index N (0–7) uses its level's link N: Levels.txt column VisN says which level it leads to, and WarpN which kind of warp it is (a LvlWarp.txt row: stairs, cave entrance…). DS1 Studio reads and edits these for you.

Seeing where a warp leads

  • On the map, warp markers read e.g. Warp · link 1 → Catacombs Level 1, or (not set) when the link is empty.
  • Select the warp cell: the Cell panel shows the level it leads to, the kind of warp, and Open buttons for that level's maps. Levels built at random by the game have no map to open.

Changing where it leads

  1. Select the warp tile and click Change where it leads… (or Connect it to a level…).
  2. Search and pick the level it should lead to, and the kind of warp.
  3. Tick also add the way back to give the target level a link back here (its map needs a warp tile with that link's number).
  4. Apply writes Levels.txt in your mod. Remove link clears it.
Note A map must be tied to a level before its warps lead anywhere: use Add to game first. If your mod ships compiled .bin tables, rebuild them afterwards (see 12.3).

7Importing DS1 and DT1 files ↑ Contents

Bring maps and tile libraries from anywhere on your computer into your mod, with the game's tables updated so they load without crashing. Both are on Home → File.

7.1Import DS1 (with its tile libraries)

  1. Import DS1… and pick the .ds1 file. It's checked first: a file the game couldn't read is refused. (A map package .zip from Export map can be picked here too: it opens the package import, tables included.)
  2. A .ds1 on its own brings none of its rows from the game's tables (Levels, LvlPrest, LvlTypes, CubeMain, AutoMap), so a warning says your own are used as they are: if they don't match the map and its tile libraries, the game can crash when it loads or while walking in it. Add it to the game afterwards and run the Compatibility check.
  3. Give the map a name (letters, digits, - and _). It will be saved as expansion/Map/<name>.ds1.
  4. Check Tile libraries this map uses: every DT1 the map names is ✓ in your game/mod, ＋ provided by a DT1 you picked, or ✗ missing.
  5. For missing ones, click Add DT1 files… or Add folders… (subfolders included). They're matched by file name, using the folders to tell same-named files apart; you can also choose a file for any library from its list.
  6. If the map names the same tiles twice in different folders (an original and a copy), a warning explains that the map would show a random mix of them; keep one copy of each (on by default) leaves out the first-listed copies. A picked DT1 with the same name as a library you already have can be chosen on that library's line to replace it.
  7. Import stays unavailable while any library is missing — find those DT1s, or tick import anyway (their tiles will show as missing and the game can't draw them).
  8. Import. The provided DT1s go into PD2assets/<folder>/ (keeping the paths the map names) and the map is pointed at them. With add it to the game next ticked, Add to game opens, pre-filled with a level that uses the same tiles — click Apply.

7.2Import DT1 (files or folders)

  1. Import DT1 ▾ → DT1 files… (one or several) or Folders… (every .dt1 inside, subfolders included).
  2. Choose the folder under PD2assets/ they go into. Keep the folder structure keeps the picked folders' subfolders.
  3. Check the list: each file's tile count, unreadable files (left out), files that will be replaced (the old one is kept as .bak). Untick any you don't want.
  4. With a map open, add them to this map's tile libraries puts each in a free File slot of the map's level type and in its Dt1Mask, so the game loads them. The free slots are shown; a level type has 32.

From the game library

Import DT1 ▾ → From game library… lists every tile library the game and your mods already have, by folder, with a search box (the map's own libraries first). Click one to see all its tiles, filtered by kind; rest the pointer on a tile to see it enlarged, click it for its details. The tiles are shown in the library's own act colours; Colours switches to the map's act, or to Act 0, which shows in magenta the colours that change between acts. Choose this library for each one you want, then Add to the map: nothing is copied (the files are already in the game), and the map's level type and Dt1Mask are updated as in Tile libraries.

Building a custom DT1 from single tiles

Switch the window to Build a custom DT1 to put together a new tile library from single tiles of any others.

  1. Open a library and click tiles to tick them (Shift+click ticks a range, Tick all shown takes everything the filter shows). Go on in other libraries: the tree marks the ones you picked from, and Picked tiles collects them all (click one to go back to its library, × to drop it).
  2. Name it. Keep the name short, 12 characters or fewer is best, using only letters, digits and _: spaces, dots, dashes and accents can break the game's tables and archives. The whole path has to fit the game's 41-character limit for tile paths, so the window says how long it may be. It goes into PD2assets/custom/ unless you change the folder.
  3. Check the summary, then Create DT1 and add it to the map.

What the new library gets:

  • Each tile exactly as it was: pixels, walkability (sub-tile flags), sound, roof height and rarity are copied byte for byte.
  • Whole pieces: a north corner wall brings its other half, and an animated tile all its frames. Special tiles (markers) can't be picked.
  • Numbers that don't clash: the game finds a cell's tile by its orientation, main and sub index among every library the level loads. A tile whose number the level already uses, or another picked tile has, would be mixed with it at random, so it gets the first free number instead; the summary lists these. Tiles you pick that share a number in their own library stay together as variants.
  • The tables: the library goes into a free File slot of the map's level type and its Dt1Mask (a level type of its own if other levels share it, as in Tile libraries), and each tile's AutoMap.txt pieces are copied from the level it came from under its new number. Originals are kept as .bak.
Colours A DT1 stores palette numbers, not colours: in game its tiles take the colours of the level's act. Tiles from another act's library can look different there; Colours → this map's act shows them as the game will. Tick Make it act-safe (Act 0 colours) to fix that: every colour of the picked tiles is snapped to the nearest one that looks the same in every act (Gimli's Act 0 palette), judged by how it looks in the act its library was drawn for (its folder's, else this map's). The window says how many picked tiles use act-specific colours, and the picked tiles show how they will look. Resting the pointer on a picked tile shows it enlarged.

8Tile libraries and the DT1 editor ↑ Contents

8.1Tile libraries

Map → Tile libraries adds or removes DT1s for the map and lets you browse every tile of any DT1 before adding it. DS1 Studio keeps the game in step: new DT1s go into free File slots of the level type (LvlTypes.txt) and the map's Dt1Mask (LvlPrest.txt) is recomputed. When two loaded DT1s have the same tile, the one listed later replaces it, as in the game.

8.2The DT1 editor

Map → DT1 editor edits a copy of any DT1: choose it in the tree on the left (every library in the game and mod, by folder), select tiles (Shift+click for a range, or From preset / From map selection), and edit their colours (8.3), pixels (8.4) or settings (8.5). Clicking a tile opens it in a zoom window you can move, resize and zoom to single pixels. Save writes a copy under a new name, or overwrites the original, and can switch your map over to it with the tables updated.

Palette Editing uses the Act 0 palette: only the 225 colours that look the same in every act, so edited tiles work in any act. Tick highlight colours that change between acts to see act-specific pixels in magenta; Make act-safe converts them.

Make act-safe: fixing odd red or purple tiles

About 30 of the palette's colours change between acts, so tiles drawn for one act (say Act 1) can show red or purple patches in a map of another act, here and in game. Map → Make act-safe lists every DT1 the map uses, how many of its pixels use act-specific colours, and a now / after preview. For each DT1, choose the act it was drawn for so the after preview looks right, then click Convert. The DT1s are saved into your mod with .bak copies, and every map using them gets the new colours.

Random red cells? If only some cells show the odd colours, in a random scatter, the map probably loads two copies of the same tiles: an original and an act-safe copy, often from an import. The game picks among both copies' variants at random. Make act-safe and the Compatibility check both detect this (“tile libraries loaded twice”) and remove the extra copy from the map's libraries, so no DT1 needs converting.

8.3Recolouring

Hue, saturation, brightness, tint, and replace a colour — for the whole file, the selected tiles, a preset's tiles, or the tiles in your map selection. The preview is exact.

8.4Pixel painting

Double-click a tile (or Paint pixels…) to paint it pixel by pixel. Only the tile's real pixels can be painted.

8.5Tile settings (.ini)

The Tile settings (ini) tab edits everything a DT1 Tools .ini holds for each tile — kind, main/sub index, rarity/frame, animated, footstep sound, roof height, direction — for one tile or many at once, each with an explanation on hover. The sub-tile flags are painted on the tile's 5×5 grid. Export .ini / Import .ini exchange settings with DT1 Tools.

9Game data ↑ Contents

9.1Data tables

Browse and edit any .txt table of the game in a spreadsheet view. Column headers have a ? explaining what the column does. The shortcuts (LvlPrest, LvlTypes, Levels, Objects, MonPreset, CubeMain) jump to the open map's row where there is one. Saving writes the table into your mod.

9.2Add to game

Makes the game load the open map. The dialog lists every field it will write, with the old value, the new value and the reason, before you click Apply. There are two ways to add a map:

  • A new level, with settings (monsters, lighting, sound, tile set) copied from a level you choose. A Levels.txt row is added as the next record, and its LvlPrest.txt row points at the map.
  • Replace the map of an existing preset level. The level's own LvlPrest row is pointed at the map. Only preset levels can do this: levels the game builds at random don't load a single map.

Either way, the tile libraries the map uses go into free File slots of the level type (LvlTypes.txt), and the preset's Dt1Mask selects them. The rules it follows come from the game's own code and tables:

RuleWhy
New rows are always added at the end: a level's Id, a preset's Def and a level type's Id equal their row number. The Expansion line doesn't count.The game reads these tables by row position. A row inserted in the middle shifts every level after it.
A level uses the first LvlPrest row with its LevelId.A second row for the same level is ignored, so an existing level is changed through its own row.
New levels are Act 5 (Act 4).The game takes the act from the level number: 109 and up is Act 5. That sets the objects, music and town.
Pal = the act the tiles were drawn for (you can change it).Pal picks the colours. The game's own Act 5 levels that reuse Act 1, 2 and 4 tiles do this.
SizeX/SizeY (all difficulties) = the map size minus one. LvlPrest SizeX/SizeY stay 0.As in every preset level of the game. The preset then fills the level.

Tile and map paths are at most 41 characters.The game adds DATA\GLOBAL\TILES\ in front, in a 60-byte buffer. The game's own longest path is 40.

The Compatibility check checks the same rules for any map already in the game, and offers one-click fixes: rows out of order (put back in Id order; no Id changes), a preset pointing at a missing level, the level size, act, palette, an overlapping position, the file count and a copied quest requirement. A new level has no connections yet: link it with warps or open it with a cube recipe. Set the DS1 header to Act 5 (the check offers it), so the map's object numbers are read as Act 5 objects.

9.3Cube recipe

Creates a new item and a Horadric Cube recipe that makes it. Pick the template item and the ingredients from lists with icons, or type your own item code (checked against the game's items). DS1 Studio takes care of the rules that otherwise crash or break the game:

  • Placement: the new item is added at the end of Misc.txt. Items are numbered by their position, so one inserted in the middle renumbers every item after it.
  • No duplicate recipes: a recipe with the same ingredients as an existing one is refused. The cube only runs the first match, so the new one would never work.
  • Never a random drop: the new item gets spawnable 0, and references to the template's code (normcode…) are changed to the new code.
  • Safe templates only: elixirs aren't offered; a copy of one crashed the game when hovered. Items of a type the base game doesn't have, like PD2's maps, need a tick first. The mod's own code handles those types and only knows the mod's own item codes.

A map item that opens this map

Pick one of your mod's map items as the template; they are listed first under Map items (open a level). The new item then opens the map you have open, and DS1 Studio makes every change for it:

  • Misc.txt: the map item, with len set to the map's level number. PD2's map items open the level named in len: "Halls of Torture Map" has len 193, which is level 193.
  • patchstring.tbl (data/local/lng/eng): the item's name, and optionally the level's name as shown in game. Every existing string keeps its number.
  • Levels.txt: the level's LevelName/LevelWarp point at that name, if you name the level.
  • CubeMain.txt: the recipe, made the way your mod's other map recipes make their maps (e.g. ,nor, lvl, ilvl).

The map must be a level in the game first. If it isn't, the dialog offers Add to game. After creating it, rebuild the .bin tables (-direct -txt) if your mod uses them.

Recipes and items DS1 Studio made are listed under Made by DS1 Studio in the dialog, where you can remove them. Remove an item only when no character holds it: a character with an item whose code is gone may not load.

9.4Compatibility check

Checks the map will load and play in game: missing tiles and DT1s, table wiring, DT1s used but not loaded by the level type, entry markers, a missing waypoint, NPCs on unwalkable ground, stacked objects, walls missing from the automap, compiled .bin reminders. Most results offer one-click fixes, and Show on map marks the cells involved. Map edits made by fixes can be undone.

Ways out. A warp tile whose link has no level in Levels.txt leads nowhere; the fix opens the warp link editor for it. A level built from this map alone, with no working warp and no waypoint, can only be left by town portal (a player without a scroll or tome is stuck): Add an exit warp… opens the link editor with the act's town chosen, then gives you the warp tile to click where players should leave. Pick a Kind of warp that suits the map before applying. If leaving by town portal is what you want, ignore the warning.

9.5The automap

Automap (A) shows the in-game automap over the map. Walls outlined in pink have no AutoMap.txt entry, so the automap draws nothing there. Map → Automap editor lists every kind of tile the map uses with the automap piece it gets: select kinds (or click spots on the preview) and pick pieces, add random variants, hide a kind on purpose, or Suggest pieces from look-alike tiles. Nothing is written until Save to AutoMap.txt.

10Sharing and exporting ↑ Contents

10.1Map packages

Export map (Home → File, or Map → Export package) puts the DS1, its DT1s, any modded object sprites and every table row the map needs into one .zip: its LvlPrest, Levels and LvlTypes rows, the CubeMain recipe made for it (with its Misc.txt item), the AutoMap rows of its level type, and LvlWarp/LvlMaze rows. The dialog lists the five main tables with how many rows each gives, and warns about any the map has none in (not added to the game yet, no cube recipe, no automap pieces). DS1 only… saves just the map file.

Import package (or Import DS1… with a .zip) merges such a zip into your mod safely: same-named rows are reused, clashing ids get new numbers (AutoMap rows follow a renumbered level type), DT1s go into free slots and the Dt1Mask is recomputed; AutoMap rows already there aren't added twice. Importing the same map twice changes nothing. The import lists which of the five tables came with the map and warns about missing ones: your own rows are used for those, and the game can crash if they don't match the map.

The maker's cube recipe and map item aren't copied: their item code, the level number the item opens and its name only fit the maker's tables. Instead, with make a cube recipe and map item for it next (on by default), the imported map opens and the Cube recipe tool starts with the maker's ingredients and item name. Create makes an item with a free code that opens the map's level number in your tables, names it and the level, and refuses a recipe your mod already uses: enter a game, cube it, and use the portal.

10.2Export image

Saves the whole map or the selection as a PNG at 100%, 50%, 25% or 12.5%, with or without objects, drawn with the layers currently shown. Sizes too large for one image are greyed out.

Copy view (Print Screen)

Home → File → Copy view, or the Print Screen key, copies the map pane exactly as it is on screen (zoom, overlays, selection, minimap) as a picture: paste it anywhere with Ctrl+V, into a chat, a document or an image editor. Windows 11 opens its own Snipping Tool on Print Screen unless Settings → Accessibility → Keyboard → Use the Print screen key to open screen capture is off; either use the button, turn that off, or give Copy view another key in Keyboard shortcuts.

10.3Export .ds1

Export map → DS1 only… saves a copy of just the map file anywhere on your computer, without touching your mod. It carries no tile libraries or table rows: to hand a map to someone, export the package.

12Safety and troubleshooting ↑ Contents

Before you start DS1 Studio is in beta. Keep a backup of your mod (and your game files) before editing.

12.1What DS1 Studio writes

  • Only into your mod folder: maps, DT1s, .txt tables, presets. Your Diablo II install is only ever read.
  • A file it replaces is kept as <name>.bak the first time, so the original survives.
  • Autosaved copies live in the app's own storage, not in your folders (1.6).

12.2If something goes wrong

If part of the app fails, it shows what happened instead of a blank window, with Try again, Close this map, Report this bug (pre-filled with the error details) and Reload DS1 Studio. Your unsaved changes are kept in the autosave.

When the game crashes

Diablo II writes every crash to a log in its folder (D2<date>.txt). Home → Crash log reads the newest crashes from your game and mod folders and says, in plain words, what they mean and what to do: a missing loading-screen image (EntryFile), a level placed too far out for the automap, AutoMap 1 on a level that isn't a town, a damaged .tbl, or a tile library, map or sprite the game couldn't open just before. The same crash repeated is shown once with a count. When the latest crash is one a map can cause, Run compatibility check finds and fixes it. Crashes it doesn't recognise are shown with where they happened, for reporting.

12.3Compiled .bin tables

The game reads compiled .bin copies of the .txt tables. After changing tables (Add to game, warps, tile libraries, cube recipes…), start the game once with -direct -txt so it rebuilds them, if your mod ships .bin files.

BGlossary ↑ Contents

DS1A map preset: a grid of cells with floor, wall, shadow and tag layers, plus objects and NPCs. The game builds levels from them.
DT1A tile library: the pictures and settings of the tiles DS1 cells refer to (chapter 8).
CellOne diamond of the map grid; each layer holds at most one tile in it.
Main / sub indexA tile's number. A cell asks for “kind + main + sub” and the game draws the DT1 tile with those numbers.
Orientation (kind)What a tile is: floor, left/right wall, corner, door, pillar/tree, roof, shadow, lower wall, special tile.
Variant / raritySeveral tiles can share a number; the game picks one at random, weighted by rarity. Animated tiles use it as their frame number.
Sub-tile flagsThe 5×5 walkability grid of a tile: block walk, sight, missiles, teleport… (3.8).
Special tileAn invisible marker: warps, entries, corpse and portal spots (2.7).
LevelA row of Levels.txt: one area of the game (a town, a dungeon floor), built from DS1 presets or at random.
LvlPrest.txtLists the DS1 files, the level each belongs to, and its Dt1Mask.
LvlTypes.txtLevel types: up to 32 DT1 File slots each.
Dt1MaskWhich of its level type's DT1 slots a DS1 loads (one bit per slot).
Warp / linkHow levels connect: Levels.txt Vis0–7 (target level) and Warp0–7 (LvlWarp row) (chapter 6).
Preset (DS1 Studio)A saved piece of map you can place again (chapter 5). Not to be confused with a DS1 “map preset”.
Act 0 paletteThe colours that look the same in every act (8.2).
Mod folderYour mod's folder; everything DS1 Studio saves goes here (1.5).
